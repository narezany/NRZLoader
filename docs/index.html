NRZLoader

Моды для Minecraft Bedrock на Android. Приложение берёт игру, которая уже стоит у вас на телефоне, и собирает из неё версию, умеющую загружать моды. Ассеты игры никуда не копируются и ничего не скачивается.

НужноЧто именно
УстройствоAndroid 8 и новее, arm64 — это почти любой телефон после 2017 года
ИграMinecraft Bedrock, установленный обычным образом
Местооколо двух размеров игры на время сборки
Компьютерне нужен

С чего начать

Скачайте NRZLoader.apk из папки dist/ в репозитории и поставьте его. Это лаунчер: он ничего не меняет в игре сам по себе, пока вы не нажмёте кнопку.

Установка

  1. Дайте лаунчеру доступ к файлам. Без него он не сможет ни прочитать игру, ни создать папку для модов. Кнопка на главном экране.
  2. Нажмите «Собрать моднутую версию». Это занимает несколько минут: игра весит сотни мегабайт, и её приходится переупаковать целиком. Из приложения можно выйти — сборка идёт в фоне и показывает прогресс в шторке.
  3. Удалите оригинал. Кнопка появится сама. Это обязательно: пересобранный пакет подписан другим ключом, и поверх старого он не встанет — установщик скажет «повреждённый пакет». Миры и настройки при этом остаются на месте, они лежат отдельно от самой игры.
  4. Установите пересобранную. Вторая кнопка. Android спросит разрешение ставить приложения из этого источника — это нормально.
  5. Дайте доступ к файлам самой игре. Отдельная кнопка в лаунчере. Игра попросила бы сама, но гораздо позже, и моды до тех пор не подхватились бы.

Про обновления игры. Когда Play Маркет обновит Minecraft, он поставит обычную версию поверх моднутой, и моды отвалятся. Собирайте заново после каждого обновления — лаунчер увидит, что игра собрана старым загрузчиком, и скажет об этом.

Куда класть моды

Загрузчик создаёт папку в корне памяти телефона:

/sdcard/NRZLoader/
├── mods/          сюда моды
├── config/        настройки загрузчика и самих модов
├── reports/       то, что моды и проверки сюда записали
└── loader.log     лог, открывается любым проводником

Мод в формате .nrzmod ставится проще: нажмите на файл в любом проводнике, лаунчер предложит установить. Отдельные .js и .so можно просто положить в mods/.

На вкладке «Моды» у каждого мода есть переключатель. Выключенный мод остаётся на месте — его id просто попадает в config/disabled.txt, и загрузчик его пропускает.

Если что-то не работает — смотрите вкладку «Лог». Загрузчик пишет туда всё: какие моды нашёл, какие пропустил и почему, что смог перехватить.

Формат .nrzmod

Это обычный zip, переименованный в .nrzmod. Внутри: 

mod.json     обязательно — описание мода
main.js      код
icon.png     иконка для карточки в лаунчере

Собрать можно чем угодно, хоть архиватором на телефоне. Файлы должны лежать в корне архива, а не в папке внутри него.

mod.json целиком

{
  "id": "nrz.example",
  "name": "Пример",
  "version": "1.0.0",
  "author": "кто-то",
  "description": "что он делает",

  "minLoader": "1.1.0",
  "maxLoader": "2.0.0",

  "links": [
    { "label": "GitHub",  "url": "https://github.com/..." },
    { "label": "Discord", "url": "https://discord.gg/..." }
  ],

  "settings": [
    { "key": "enabled", "label": "Включено", "type": "toggle", "default": true },
    { "key": "power",   "label": "Сила",     "type": "slider",
      "min": 0, "max": 1, "default": 0.5 },
    { "key": "mode",    "label": "Режим",    "type": "choice",
      "options": ["а", "б"], "default": "а" },
    { "key": "name",    "label": "Имя",      "type": "text", "default": "" }
  ]
}
ПолеЧто делает
idобязательно, должно быть уникальным: по нему мод узнают настройки и переключатель
minLoader, maxLoader версии загрузчика, с которыми мод работает. Не подходит — лаунчер напишет об этом на карточке, а загрузчик такой мод не запустит
linksкнопки на карточке мода. Берутся только http и https
settingsлаунчер сам нарисует контролы и положит выбранное в config/<id>.json

Мод читает свои настройки одной строкой:

var options = nrz.readJson("config/nrz.example.json") || {};
if (options.enabled) { /* ... */ }

Лаунчер про смысл настроек не знает ничего — он только рисует и записывает. Поэтому добавить настройку можно, не дожидаясь, пока лаунчер про неё узнает.

Что умеет мод

Скриптовый мод — это JavaScript, который загрузчик запускает внутри игры. В каждом контексте лежит объект nrz.

Файлы и лог

nrz.log("привет");                  // строка уйдёт в loader.log

nrz.writeJson("state.json", { runs: 1 });
var state = nrz.readJson("state.json");

nrz.writeFile("notes.txt", "текст");
var text = nrz.readFile("notes.txt");
nrz.listDir(".");                   // массив имён
nrz.deleteFile("notes.txt");

nrz.info();                         // что вообще доступно

Файлы мода живут только внутри NRZLoader/. Мод — это код, который вы решили поставить, но это ещё не повод отдавать ему весь телефон.

Экранные эффекты

Загрузчик перехватывает момент, когда готовый кадр уходит в систему, копирует его в текстуру и рисует обратно через шейдер. Игре про это знать не нужно, поэтому эффекты не ломаются от её обновлений. 

nrz.fx.set({ crt: 0.7, chroma: 0.3 });   // несколько сразу, сила от 0 до 1
nrz.fx.clear();
nrz.fx.info();                            // {names, active, shader, error, drawing}
ИмяЧто делает
crtстрочки развёртки и цветная маска старого монитора
fisheyeрыбий глаз
glitchполосы уезжают вбок
chromaрасслоение цвета по краям
pixelateкрупные пиксели
waveкартинка идёт волнами
vignetteзатемнение к краям
grayscaleчёрно-белое
invertинверсия

Без всякого мода то же самое включается строкой в config/bindings.conf:

screen.effects = crt=0.6,chroma=0.2

Если nrz.fx.info().drawing остаётся false — кадр уходит мимо OpenGL, и эффекты до экрана не доходят. Такое бывает на устройствах, где игра рисует через Vulkan.

Свой шейдер 1.1.0

Список встроенных эффектов кончается — свой не кончается. Мод пишет фрагментный шейдер, загрузчик добавляет обвязку и собирает его. 

nrz.fx.uniform("heat", 0.4);
nrz.fx.shader([
  "uniform float heat;",
  "vec3 effect(vec2 uv) {",
  "    vec3 c = texture2D(uTex, uv).rgb;",
  "    float v = dot(c, vec3(0.299, 0.587, 0.114));",
  "    return vec3(v * heat * 2.0, v, 1.0 - v);",
  "}",
].join("\n"));

nrz.fx.noShader();   // обратно к встроенным
Уже объявленоЧто это
vUvкоордината пикселя, от 0 до 1
uTexготовый кадр игры
uResразмер экрана в пикселях
uTimeсекунды с запуска

Всё остальное мод объявляет сам и задаёт через nrz.fx.uniform. Достаточно написать vec3 effect(vec2 uv); если нужен полный контроль, можно написать свой void main — тогда обвязку не добавят.

Шейдер собирается на том потоке, где идёт отрисовка, то есть кадром позже. Поэтому ошибка в нём появляется не сразу, а в nrz.fx.info().error.

Окна поверх игры

Интерфейс игры не тронуть, не правя её собственные файлы, поэтому окна берутся у системы. Внутри — обычный html с css. 

nrz.window.open("my.hud", {
    x: 24, y: 120,
    width: 320, height: 0,   // 0 — по содержимому
    touchable: false,        // false — тапы проходят насквозь в игру
    html: "<b style='color:#fff'>0, 64, 0</b>",
});

nrz.window.setHtml("my.hud", "<b>новые координаты</b>");
nrz.window.move("my.hud", { x: 40, y: 200 });
nrz.window.eval("my.hud", "document.body.style.opacity = 0.5");
nrz.window.close("my.hud");
nrz.window.list();
nrz.window.info();           // {available, reason}

touchable: false — для показометров: координаты, FPS, что угодно; тапы уходят в игру. true — для пультов с кнопками.

Как окно разговаривает обратно

Страница внутри окна отправляет сообщения, мод их забирает:

// внутри html
<button onclick="nrzhost.send('привет')">кнопка</button>

// в моде
var messages = nrz.window.poll("my.hud");   // массив строк

Но забирать их надо в цикле, а таймера у мода может и не быть. Поэтому сообщение, начинающееся с nrz:, обрабатывает сам загрузчик, и мод для этого не нужен вовсе: 

<button onclick="nrzhost.send('nrz:fx crt=0.7')">CRT</button>
<button onclick="nrzhost.send('nrz:fx')">выключить</button>
<button onclick="nrzhost.send('nrz:log что-то случилось')">в лог</button>
<button onclick="nrzhost.send('nrz:close')">закрыть окно</button>

Готовый пример — мод panel.nrzmod в репозитории.

Окошко с показателями 1.14.0

Поверх игры можно держать сводку вроде отладочного экрана: сколько кадров, сколько тактов, сколько идёт игра и что игрок делает прямо сейчас. 

NRZLoader 1.14.0
58 fps, 20 tps, 143s

[x] breaking 214
[ ] placing 61
[ ] attacking 3
[ ] eating 12
[ ] swimming 0

Включается строкой hud = on в config/bindings.conf (по умолчанию включено) и требует включённой разведки — числа берутся из неё.

Откуда числа. Не из полей игрока: где они лежат, неизвестно. Загрузчик считает вызовы виртуальных методов, а какой номер что означает — выяснено на записи реальной игры. Поэтому здесь нет ни координат, ни угла камеры: это числа внутри объекта, а не вызовы, и прочерк честнее выдуманного значения.

Номера у каждой сборки игры свои, поэтому лежат в настройках. Свой номер узнаётся так же, как узнавались эти: включить разведку, поделать в игре одно и то же действие, посмотреть в reports/slots-timeline.txt, какой счётчик растёт только тогда. 

hud.break = 111
hud.place = 103,112
hud.hit   = 144
hud.eat   = 68,69
hud.swim  = 37
hud.frame = 35
hud.tick  = 25

Вид правится файлом. При первом запуске загрузчик кладёт рядом с настройками config/hud.html и дальше только читает его. Шрифт, цвета, порядок строк, вообще вся вёрстка — обычный html: открыл текстовым редактором, поменял, перезапустил игру. Пересобирать ничего не нужно.

Единственное требование к файлу — объявить функцию u(d), которой загрузчик несколько раз в секунду отдаёт числа:

ПолеЧто это
d.vверсия загрузчика
d.fкадров в секунду
d.tтактов в секунду (у игры их 20)
d.uсколько идёт игра
d.sпоказатели: [идёт ли сейчас, сколько всего]

Порядок в d.s — тот же, что порядок ключей hud.*. Если файл испортить до неработоспособности, окно останется пустым, а игра — целой: страница живёт в отдельном окне системы и до игры не дотягивается.

Нативные моды

Мод можно написать и на C++ — это будет .so-библиотека. Она получает доступ к перехвату функций и к шине событий: 

#include "mcbe/mod_api.h"
#include "mcbe/events.h"

static const McbeApi* api;

static void on_hurt(McbeEvent* event, void* user) {
    McbeDamageEvent* damage = (McbeDamageEvent*)event->data;
    damage->amount *= 0.5f;      // половина урона
}

const McbeModInfo* mcbe_mod_info(void) {
    static const McbeModInfo info = {
        MCBE_ABI_VERSION, "my.mod", "Мой мод", "1.0.0", "1.21.131"
    };
    return &info;
}

McbeResult mcbe_mod_init(const McbeApi* a) {
    api = a;
    api->subscribe(MCBE_EVENT_ACTOR_HURT, on_hurt, NULL);
    return MCBE_OK;
}

События работают там, где загрузчик смог найти нужные функции игры по именам. На розничной сборке для Android имён нет — подробности ниже. Скриптовые моды от этого не зависят.

Настройки загрузчика

NRZLoader/config/bindings.conf, создаётся сам при первом запуске:

НастройкаЗначенияЧто делает
script.run_in all · game · first · none в каких контекстах запускать скриптовые моды
storage.request auto · always · never спрашивать ли доступ к файлам при запуске игры
screen.effects crt=0.6,chroma=0.2 эффекты, включённые сразу, без мода

Версии

Версия загрузчика видна в трёх местах:

  • на главном экране лаунчера — какая версия у вас установлена;
  • на карточке игры — каким загрузчиком собрана стоящая игра;
  • в первой строке loader.log.

Если игра собрана более старым загрузчиком, лаунчер это заметит и предложит пересобрать.

Мод объявляет minLoader и maxLoader. Проверка стоит именно в загрузчике, а не в моде: мод, который ошибается насчёт загрузчика, не может сам заметить свою ошибку.

Чего он не может

Честно, потому что от этого зависит, стоит ли вам вообще это ставить.

Minecraft Bedrock написан на C++, и в розничной сборке для Android вырезаны все имена собственного кода Mojang. Это проверено на настоящей библиотеке: поиск по Actor, BlockLegacy, ItemStack даёт ноль совпадений при 212 мегабайтах кода. Java-мод цепляется за классы игры по именам — здесь их физически нет.

ЧтоКак оно
Экранные эффекты, свои шейдерыработают: перехват идёт на системном уровне
Окна поверх игрыработают: окна берутся у Android
Файлы, настройки, лог у модаработают
Официальный скриптовый API Minecraftработает, если он есть в вашей сборке
Менять урон, блоки, поведение мобовнет: имён этих функций в клиенте не осталось
Камера, рендер мира на блокнет, по той же причине

Что с этим можно сделать

Mojang бесплатно публикует выделенный сервер Bedrock под Windows и Linux. Это тот же исходный код, только без рендера, и на нём построены LiteLoaderBDS и LeviLamina.

Отдельного файла символов Mojang к нему не кладёт. Так написано во многих местах, включая прежнюю версию этой страницы, но это неправда: проверено на 1.26.36.1 — и в Linux-сборке, и в Windows-сборке таблица символов вырезана, .debug_* нет, .pdb рядом нет, в динамической таблице 396 имён, и все они системные. Имена классов у таких проектов восстановлены вручную и лежат в их собственных заголовках.

Мостом может служить RTTI: если сборка клиента его не вырезала, от строки с именем класса есть дорога к таблице виртуальных методов, а номер метода в ней скажет сервер. В лаунчере есть кнопка «Заглянуть внутрь игры» — она за минуту отвечает, открыт этот путь или нет, и кладёт отчёт в reports/rtti.txt.

Сборка из исходников

# загрузчик, нужен Android NDK r25+
ANDROID_NDK=$HOME/Android/Sdk/ndk/27.2.12479018 ./build.sh

# классы, которые дописываются в игру

# лаунчер

# тесты
./tests/run_tests.sh        # движок перехвата, под ARM64 в эмуляторе

Правовая сторона

Инструмент ничего не скачивает и не обходит защиту: он работает с вашей копией игры, которую вы предоставляете сами, и ассеты Minecraft внутрь него не попадают.

При этом модификация клиента расходится с условиями магазина Microsoft, а на серверах и Realms изменённый клиент могут счесть читерством. Держите такие сборки для одиночной игры и своих серверов.

Если нужен способ без всего этого — у Bedrock есть официальные аддоны со скриптингом на JavaScript. Умеют меньше, но не ломаются от каждого обновления.
