# NRZLoader

Загрузчик модов для Minecraft Bedrock на Android (arm64), нацеленный на ветку
**1.21.13x** — это то, что на Java-нумерации соответствует 1.21.11.

Моды — обычные `.so`-библиотеки. Загрузчик находит функции игры, перехватывает
их и раздаёт модам события: тик мира, урон, вход и выход игрока.

## Сразу самое важное

Игра написана на **C++**, а не на Java и не на C#. Это значит, что готовых имён
классов и полей, как в Java-модах, здесь нет — есть машинный код и таблица
символов. Поэтому загрузчик всегда привязан к конкретной сборке игры: вышло
обновление — имена и адреса надо пересобрать заново.

**Что здесь проверено на практике, а что нет:**

| Часть | Состояние |
|---|---|
| Перехват функций на ARM64 (релокация, трамплин, снятие) | проверено, 50 тестов на реальном ARM64-коде |
| Поиск функций по символам, в том числе внутри APK без распаковки | проверено, 17 тестов |
| Способ внедрения через зависимость ELF | проверено: линкер сам грузит загрузчик |
| Сборка под Android arm64 через NDK | собирается, `libnrzloader.so` ≈ 1 МБ |
| Имена функций самой игры | проверено на 1.26.23.1: **их там нет**, см. ниже |
| Точки входа движка скриптов | подтверждены в 1.26.23.1, привязки в `bindings/1.26.conf` |
| **Запуск на реальном устройстве** | **не проверено — здесь нет ни игры, ни телефона** |

## Главное про розничные сборки

Разбор настоящей библиотеки из 1.26.23.1 (arm64, 321 МБ) показал:

- 89 484 экспортируемых имени, секции `.symtab` нет вообще;
- поиск по `Actor`, `BlockLegacy`, `ItemStack` даёт **ноль совпадений**;
- то, что находится по словам `Level` и `Player`, принадлежит посторонним
  библиотекам (`HCSettingsSetTraceLevel`, `cohtml::media::MediaPlayer`);
- при этом `.text` занимает 212 МБ.

Вывод: имена собственного кода Mojang вырезаны, и перехватывать геймплейные
функции по имени на розничном клиенте нельзя. Искать их по байтовым сигнатурам
в 212 мегабайтах кода технически возможно, но это месяцы ручной работы в
дизассемблере, и частично заново после каждого обновления.

**Что уцелело — движок JavaScript.** Он вкомпилирован в игру целиком, вместе с
публичным интерфейсом, и именно на нём работает официальный скриптовый API
Minecraft. Подтверждённые имена:

```
_ZN2v87Context3NewE...        создание контекста
_ZN2v86Script3RunE...         запуск скрипта
_ZN2v88Function4CallE...      вызов функции
_ZN2v817RegisterExtensionE... регистрация своего расширения
```

Поэтому загрузчик цепляется за них: ловит создание контекста JavaScript и
отдаёт модам указатели на движок. Это заметно устойчивее нативных хуков —
такая привязка не рассыпается от перестановки кода при обновлении игры.

Нативные привязки (`level.tick` и прочие) остались в проекте: на выделенном
сервере символы есть, и там они работают. На розничном клиенте они просто не
активируются, о чём загрузчик пишет в лог.

## Как это работает

1. **Внедрение.** В `libminecraftpe.so` внутри APK дописывается зависимость от
   `libnrzloader.so`. Системный загрузчик Android видит её и подгружает нашу
   библиотеку автоматически, до того как игра начнёт работать. Правка кода на
   Java или smali не нужна вообще.
2. **Поиск функций.** Адрес функции ищется четырьмя способами по очереди:
   `dlsym` → таблицы символов из файла → заранее собранная карта смещений →
   поиск по байтовой сигнатуре. Если один способ не сработал, пробуется
   следующий.
3. **Перехват.** Первые 16 байт функции заменяются на абсолютный переход к
   нашему коду. Затёртые инструкции переносятся в отдельный буфер, откуда
   оригинальная функция по-прежнему вызывается. Инструкции, которые зависят от
   своего адреса (`adrp`, `ldr literal`, `b`, `bl`, `cbz`, `tbz`, `b.cond`),
   при переносе переписываются. Незнакомую инструкцию загрузчик не трогает —
   он честно отказывается ставить хук, вместо того чтобы испортить код.
4. **События.** Поверх хуков работает шина событий, на которую подписываются
   моды.

## Готовая сборка

В `dist/` лежит собранный `libnrzloader.so` под arm64-v8a — компилировать
ничего не надо. Зависит только от системных библиотек (`libc`, `libm`,
`libdl`, `liblog`), стандартная библиотека C++ вшита внутрь, так что в
процессе игры ему ничего дополнительного не требуется.

### Установка целиком с телефона

В Termux:

```bash
pkg install python patchelf
python patch_apk.py Minecraft.apk libnrzloader.so -o patched.apk
```

Скрипт допишет зависимость от загрузчика в библиотеку игры и вложит его
внутрь APK. Полученный `patched.apk` надо подписать — проще всего открыть его
в MT Manager и сохранить, он подпишет сам. Затем удалить старую игру и
установить пропатченную (подпись другая, поверх не встанет).

### Где что лежит

Загрузчик сам создаёт при запуске папку в корне памяти:

```
/sdcard/NRZLoader/
├── mods/          сюда моды: нативные .so и скриптовые .js
├── config/        bindings.conf и symbols.map
└── loader.log     лог, открывается любым проводником
```

Логи писать в файл — потому что logcat на телефоне без ПК читается только
через Shizuku или root, а это лишний барьер. Лог перезаписывается при каждом
запуске игры и сбрасывается на диск после каждой строки, так что при падении
последняя строка сохранится.

Если создать папку в корне не вышло (нет разрешения на все файлы), загрузчик
по очереди пробует другие места и в итоге откатывается в свой каталог внутри
`Android/data`. Какой путь выбран — написано в первых строках лога.

**Про доступ ко всем файлам** это делается само:

1. `patch_apk.py` дописывает `MANAGE_EXTERNAL_STORAGE` прямо в
   `AndroidManifest.xml`. Манифест внутри APK не текстовый, а в двоичном
   формате Android, поэтому в `tools/axml.py` лежит небольшой редактор этого
   формата: он добавляет строку в общий пул и вставляет элемент, не трогая
   ничего остального.
2. Если при запуске загрузчик не смог создать папку в корне, он открывает
   системный экран выдачи разрешения. Для этого нужен доступ к Java-части
   Android, а его загрузчик получает, перехватив входную точку игры: первым
   аргументом любой JNI-функции идёт `JNIEnv`, а вторым у инициализации
   активности — сама активность, которой достаточно для запроса.

Разрешение спрашивается один раз за запуск и только если папку в корне
создать не удалось, так что при выданном доступе экран больше не появится.

## Сборка из исходников

Нужен Android NDK r25 или новее.

```bash
ANDROID_NDK=$HOME/Android/Sdk/ndk/27.2.12479018 ./build.sh
```

Получится `build/libnrzloader.so` и пример мода
`build/examples/hello_mod/libhello_mod.so`.

## Тесты

```bash
sudo apt install g++-aarch64-linux-gnu qemu-user patchelf
./tests/run_tests.sh
```

Тесты собираются под ARM64 и гоняются в эмуляторе, потому что проверять движок
перехвата на x86 бессмысленно — там другой машинный код.

## Как пользоваться

### Шаг 1. Узнать настоящие имена функций

Качать APK со сторонних сайтов не нужно и не стоит: имена берутся из той
копии игры, которая уже стоит на устройстве. Подходит любая версия — загрузчик
не привязан к конкретному номеру, он читает то, что ему дали.

**Прямо на телефоне, без ПК** (Termux):

```bash
pkg install python
bash tools/on_device.sh
```

Скрипт сам найдёт установленную игру через `pm path`, разберёт её и положит
результат в `~/mcbeloader-out`. Ничего никуда не отправляется.

**На компьютере:**

```bash
python3 tools/symgen.py minecraft.apk -o out
```

Современная игра ставится сплитом из нескольких APK, и библиотека лежит не в
основном, а в файле под конкретную архитектуру. Передавайте все пути сразу:

```bash
python3 tools/symgen.py base.apk split_config.arm64_v8a.apk -o out
```

На выходе три файла:

| Файл | Что это |
|---|---|
| `symbols.map` | все символы со смещениями, для загрузчика |
| `bindings.conf` | заготовка привязок событий к функциям |
| `report.txt` | короткая выжимка: что за сборка и какие функции нашлись |

`report.txt` — маленький и содержит только имена и смещения, без кода игры;
его удобно показать, когда просишь помощи с настройкой.

Поискать что-то конкретное:

```bash
python3 tools/symgen.py minecraft.apk --search Level::tick
```

Если в вашей сборке символов нет вообще — придётся искать функции по байтовым
сигнатурам, в `bindings.conf` для этого есть форма `sig:`.

### Шаг 2. Вшить загрузчик в APK

```bash
python3 tools/patch_apk.py minecraft.apk build/libnrzloader.so -o patched.apk
```

APK нужно подписать. Скрипт подпишет сам, если найдёт `apksigner` из Android
build-tools. На телефоне проще открыть файл в MT Manager или APK Editor — они
подписывают при сохранении.

Дальше старую игру надо удалить, а `patched.apk` установить (подпись другая,
поверх не встанет).

### Шаг 3. Положить файлы на устройство

```
/sdcard/Android/data/com.mojang.minecraftpe/files/
├── mcbeloader/
│   ├── bindings.conf     <- из шага 1
│   └── symbols.map       <- из шага 1
└── mods/
    └── libhello_mod.so
```

### Шаг 4. Смотреть лог

```bash
adb logcat -s NRZLoader NRZMod
```

Загрузчик пишет, какие привязки ожили, а какие нет, и какие моды загрузились.
Если функция не нашлась — это строчка в логе, а не падение игры.

## Как написать мод

```c
#include "mcbe/mod_api.h"
#include "mcbe/events.h"

static const McbeApi* api;

static void on_hurt(McbeEvent* event, void* user) {
    McbeDamageEvent* damage = (McbeDamageEvent*)event->data;
    damage->amount *= 0.5f;   // половина урона
    // event->cancelled = 1;  // или вообще отменить
}

const McbeModInfo* mcbe_mod_info(void) {
    static const McbeModInfo info = {
        MCBE_ABI_VERSION, "my.mod", "Мой мод", "1.0.0", "1.21.131"
    };
    return &info;
}

McbeResult mcbe_mod_init(const McbeApi* a) {
    api = a;
    api->subscribe(MCBE_EVENT_ACTOR_HURT, on_hurt, NULL);
    return MCBE_OK;
}
```

Полный пример — в `examples/hello_mod/`.

Указатели на объекты игры (`player`, `actor`, `level`) намеренно отдаются как
непрозрачные: смещения полей внутри классов Minecraft меняются от сборки к
сборке и в этот интерфейс не входят. Нужен конкретный метод — достаньте его
через `api->resolve_symbol()`.

## Мод на JavaScript

Скриптовый мод — это `.js` в `mods/` или `main.js` внутри `.nrzmod`. Загрузчик
кладёт в каждый контекст объект `nrz`:

```js
nrz.log("привет");                        // строка уйдёт в NRZLoader/loader.log
nrz.writeJson("state.json", { runs: 1 }); // файлы — только внутри NRZLoader/
var state = nrz.readJson("state.json");
nrz.listDir(".");
nrz.info();                               // что вообще доступно
```

### Эффекты поверх картинки

Загрузчик перехватывает момент, когда готовый кадр уходит в систему, копирует
его в текстуру и рисует обратно через шейдер. Игре про это знать не нужно —
поэтому эффекты работают, не завися ни от одного имени внутри самой игры.

```js
nrz.fx.set({ crt: 0.7, chroma: 0.3 });    // несколько сразу, сила от 0 до 1
nrz.fx.clear();
nrz.fx.info();                            // {names, active, drawing}
```

Имена: `pixelate`, `fisheye`, `wave`, `glitch`, `chroma`, `crt`, `vignette`,
`grayscale`, `invert`. То же самое включается и без мода — строкой
`screen.effects = crt=0.6` в `config/bindings.conf`.

Если `drawing` остаётся `false` — кадр уходит мимо OpenGL (Vulkan), и до
экрана эффекты не доходят.

### Свои окна поверх игры

Интерфейс игры не тронуть, не правя её же файлы, поэтому окна берутся у
системы. Внутри — обычный html.

```js
nrz.window.open("my.hud", {
    x: 24, y: 120, width: 320, height: 0,  // 0 — по содержимому
    touchable: false,                      // false — тапы проходят в игру
    html: "<b style='color:#fff'>0, 64, 0</b>",
});
nrz.window.setHtml("my.hud", "<b>новые координаты</b>");
nrz.window.close("my.hud");
```

Нужно разрешение «поверх других приложений» — кнопка для него есть в лаунчере.
Страница внутри окна отвечает моду через `nrzhost.send(...)`, мод забирает
сообщения через `nrz.window.poll("my.hud")`.

Сообщение, начинающееся с `nrz:`, обрабатывает сам загрузчик, и мод для этого
не нужен вовсе — это важно, потому что таймера у мода может и не быть:

```html
<button onclick="nrzhost.send('nrz:fx crt=0.7')">CRT</button>
<button onclick="nrzhost.send('nrz:close')">закрыть</button>
```

Готовый пример — `examples/panel/`: окно с кнопками эффектов.

### Свой шейдер

Список встроенных эффектов кончается — свой не кончается. Мод пишет фрагментный
шейдер, загрузчик добавляет к нему обвязку и собирает его на том потоке, где
рисует.

```js
nrz.fx.uniform("heat", 0.4);
nrz.fx.shader([
    "uniform float heat;",
    "vec3 effect(vec2 uv) {",
    "    vec3 c = texture2D(uTex, uv).rgb;",
    "    return c * (1.0 + heat);",
    "}",
].join("\n"));

nrz.fx.noShader();   // обратно к встроенным
```

Объявлять `vUv`, `uTex`, `uRes` и `uTime` не нужно — они уже есть. Всё
остальное мод объявляет сам и задаёт через `nrz.fx.uniform`. Сборка идёт кадром
позже, поэтому ошибка в шейдере появляется в `nrz.fx.info().error`, а не сразу.

## Манифест мода

`mod.json` внутри `.nrzmod` описывает не только имя:

```json
{
  "id": "nrz.example",
  "name": "Пример",
  "version": "1.0.0",
  "author": "кто-то",
  "description": "что он делает",

  "minLoader": "1.1.0",
  "maxLoader": "2.0.0",

  "links": [
    { "label": "GitHub", "url": "https://github.com/..." },
    { "label": "Discord", "url": "https://discord.gg/..." }
  ],

  "settings": [
    { "key": "enabled", "label": "Включено", "type": "toggle", "default": true },
    { "key": "power", "label": "Сила", "type": "slider", "min": 0, "max": 1, "default": 0.5 },
    { "key": "mode", "label": "Режим", "type": "choice", "options": ["а", "б"], "default": "а" },
    { "key": "name", "label": "Имя", "type": "text", "default": "" }
  ]
}
```

`minLoader` и `maxLoader` — версии загрузчика, с которыми мод работает. Если
версия не подходит, лаунчер пишет об этом на карточке, а загрузчик такой мод
не запускает вовсе. Свою версию загрузчик пишет в первой строке лога, лаунчер —
на главном экране, и она же вшивается в собранный пакет игры.

`links` рисуются кнопками на карточке мода. Берутся только `http`/`https`.

`settings` рисуются лаунчером; выбранное он кладёт в `config/<id>.json`, откуда
мод читает это обычным `nrz.readJson("config/<id>.json")`. Лаунчер ничего в них
не понимает, поэтому мод волен добавлять настройки, не дожидаясь лаунчера.

Тумблер на карточке выключает мод, ничего не удаляя: id попадает в
`config/disabled.txt`, и загрузчик его пропускает.

## Выделенный сервер как словарь

Mojang бесплатно публикует Bedrock Dedicated Server под Windows и Linux, и
рядом с ним кладёт файл символов. Это тот же самый исходный код, что и в
клиенте, только собранный без рендера и интерфейса. Именно на этом построены
LiteLoaderBDS и LeviLamina — моддинг сервера с настоящими именами классов.

Что это даёт клиенту на Android:

- **имена и устройство классов** — `Actor`, `Level`, `BlockLegacy`, `ItemStack`,
  порядок виртуальных методов, смещения полей;
- **чего не даёт — адреса.** Сервер собран под x86-64 другим компилятором.
  Перенести смещения нельзя, там другой машинный код.

Мост между ними — то, что переживает пересборку: строковые литералы, редкие
константы, номер метода в таблице виртуальных функций. Сервер говорит, что
`Actor::hurt` — это, скажем, слот 42, а в клиенте остаётся найти саму таблицу.

Найти её можно через RTTI: у класса с виртуальными методами рядом с таблицей
лежит `typeinfo`, а в нём строка с именем класса. Строки в `.rodata` не
вырезают. Есть ли они в клиенте — проверяется одной командой:

```bash
python3 tools/probe_rtti.py base.apk split_config.arm64_v8a.apk
```

Зонд проверен на двух специально собранных библиотеках: с RTTI и с `-fno-rtti`,
обе полностью лишённые таблицы символов. Первую он опознаёт, вторую — нет.

Если RTTI на месте — геймплейные функции находятся механически, и до модов
уровня Java становится заметно ближе. Если вырезан — остаются строки-якоря:
искать функцию по коду, который обращается к известной строке. Дольше, но тоже
без ручного дизассемблера.

Оговорка, которая не отменяется ни в одном из случаев: рендер, интерфейс и
камера в серверную сборку не входят вовсе. Экранные эффекты и окна как работали
через свои перехваты, так и будут.

## Что дальше

- Проверить имена функций на настоящей сборке и заполнить `bindings/`.
- Событий пока четыре. Добавить новое — это одна структура в
  `src/core/bindings.cpp` плюс константа в `include/mcbe/events.h`.
- Только `arm64-v8a`. Под 32-битный `armeabi-v7a` нужен свой релокатор:
  у ARM другая система команд и режим Thumb.
- Хуки ставятся без остановки других потоков. Если игра выполняет ровно эти
  16 байт в момент установки — теоретически возможна гонка. На практике хуки
  ставятся один раз при запуске, но честнее это упомянуть.

## Правовая сторона

Инструмент ничего не скачивает и не обходит защиту: он работает с **вашей**
копией игры, которую вы предоставляете сами. Модификация клиента расходится с
условиями магазина Microsoft, а на серверах и Realms изменённый клиент может
быть расценён как читерство. Держите такие сборки для одиночной игры и своих
серверов.

Если нужен способ без всего этого — у Bedrock есть официальные аддоны со
скриптингом на JavaScript (`@minecraft/server`). Умеют меньше, но не ломаются
от каждого обновления игры.
